# מאירים — מערכת ניהול פעילות

מערכת ווב לניהול הפעילות של עמותת "מאירים": ניהול משפחות נתמכות, חלוקות סלי מזון עם
מסלול מותאם על מפה, פעילויות ושיבוץ מדריכים/מתנדבים, דיווחי שעות שבועיים, צ׳אט צוותי
וצ׳אט לכל פעילות. ממשק בעברית (RTL), מותאם למובייל.

## התקנה והרצה מקומית

```bash

npm install

# 2. יצירת קובץ סביבה (ראה "משתני סביבה" למטה)
```

## הקמת Supabase

1. צור פרויקט חדש ב-[supabase.com](https://supabase.com).
2. פתח את **SQL Editor** והרץ את הקובץ [`meirim-schema.sql`](./meirim-schema.sql)
   **על מסד נתונים ריק, בלחיצה אחת**. הוא יוצר את כל הטבלאות, ה-enum-ים,
   הטריגרים, פונקציות ה-RPC, מדיניות ה-RLS, באקטי ה-Storage ורישום ה-Realtime,
   וגם מזין ארבעה סניפים לדוגמה (שדרות, נתיבות, אופקים, אשקלון).

   > ⚠️ **החלק התחתון של הקובץ** ("השלמות סכמה — שוחזרו מקוד הלקוח") מיועד
   > להרצה **על DB נקי בלבד**. אין להריץ אותו על מסד נתונים קיים/חי — הוא עלול
   > לדרוס פונקציות ופוליסות קיימות. ראה [תחזוקת סכמת מסד הנתונים](#תחזוקת-סכמת-מסד-הנתונים).

3. **Authentication → Providers**: ודא ש-**Email** מופעל. אם רוצים כניסה עם Google,
   הפעל גם את ספק **Google** והגדר את ה-redirect ל-origin של האתר.
4. **Storage**: הסקריפט יוצר שני באקטים פרטיים — `door-photos` ו-`activity-files`.
   ודא שהם קיימים תחת **Storage** לאחר ההרצה.
5. העתק מ-**Project Settings → API** את ה-`Project URL` ואת ה-`publishable`/`anon key`
   לתוך `.env.local` (ראה למטה).

## משתני סביבה

צור קובץ `.env.local` בשורש הפרויקט (הוא כבר ב-`.gitignore` — לא נשמר ב-git):

```env
VITE_SUPABASE_URL=https://<your-project-ref>.supabase.co
VITE_SUPABASE_ANON_KEY=<your-publishable-or-anon-key>
```

- שני המשתנים **חובה** — האפליקציה זורקת שגיאה ברורה אם הם חסרים (`src/lib/supabase.js`).
- המפתח הזה הוא **publishable/anon** ומיועד לחשיפה בצד הלקוח; האבטחה נאכפת ע"י
  **RLS** במסד הנתונים. אין להשתמש כאן ב-`service_role key`.
- ב-Netlify: הגדר את שני המשתנים תחת **Site settings → Environment variables**.

## בנייה ופריסה

## תפקידים והרשאות

ארבעה תפקידים (enum `user_role`), עם לשוניות ונתונים נראים לפי תפקיד. ההרשאות
נאכפות **גם** בצד הלקוח (`src/App.jsx`, `TABS_BY_ROLE`) **וגם** במסד הנתונים (RLS):

| תפקיד        | תיאור            | גישה עיקרית                                              |
| ------------ | ---------------- | -------------------------------------------------------- |
| `admin`      | מנכ״ל / הנהלה     | הכל, בכל הסניפים, כולל "אפיון ותיעוד"                     |
| `service`    | בת שירות לאומי    | הכל **בסניף שלה** (חוץ מ"אפיון ותיעוד")                   |
| `instructor` | מדריך/ה          | לוח בקרה, פעילויות, חלוקות, צ׳אט, דיווחים                 |
| `volunteer`  | מתנדב/ת בשטח      | לוח בקרה, פעילויות, חלוקות, צ׳אט (קריאה בעיקר)            |

> משתמש חדש שנרשם מקבל תפקיד `volunteer` כברירת מחדל (טריגר `handle_new_user`),
> ומשלים בחירת תפקיד ופרטים במסך `RoleSelector` (מזוהה לפי היעדר `phone` בפרופיל).

## תחזוקת סכמת מסד הנתונים

הקובץ `meirim-schema.sql` הוא **מקור אמת ידני** — הוא לא מסונכרן אוטומטית עם ה-DB.
כשמשנים את המבנה (עמודה/טבלה/פונקציה/פוליסה) דרך לוח הבקרה של Supabase, יש לעדכן
גם את הקובץ, אחרת הוא מפגר אחרי ה-DB החי.

**הדרך המומלצת** — לייצא את הסכמה האמיתית מה-DB החי באמצעות ה-CLI:

```bash
# מייצא את המבנה המדויק (ללא נתונים) של סכמת public
supabase db dump --schema public -f meirim-schema.sql
```

לחלופין, לצפייה בהגדרה המדויקת של פונקציה או פוליסה מתוך **SQL Editor**:

```sql
-- גוף פונקציה
SELECT pg_get_functiondef('public.archive_activity'::regprocedure);

-- כל הפוליסות בסכמה
SELECT * FROM pg_policies WHERE schemaname = 'public';
```

> החלק "השלמות סכמה — שוחזרו מקוד הלקוח" בתחתית `meirim-schema.sql` שוחזר מקריאת
> קוד הלקוח (בגלל פער שנוצר בין הקובץ ל-DB החי). מומלץ להחליף אותו בייצוא אמיתי
> (`supabase db dump`) בהזדמנות הראשונה, כדי שהטיפוסים והפוליסות יהיו מדויקים ל-100%.

## שמירה על הפרויקט "ער"

ב-[`.github/workflows/keepalive.yml`](./.github/workflows/keepalive.yml) יש workflow
שרץ כל ~5 ימים ומבצע פינג ל-Supabase (מונע השהיה של פרויקט חינמי אחרי 7 ימי חוסר
פעילות), וכן commit קטן מדי פעם (מונע מ-GitHub להשבית את התזמון אחרי 60 יום).
אפשר גם להריץ אותו ידנית מלשונית **Actions → Run workflow**.
